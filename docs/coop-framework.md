# 附体双人原型

## 控制与外观

这是同一键盘上的本地双人合作框架，不包含网络联机。

- **猎人**：WASD 移动并决定面向方向；Space 沿面向方向射击。猎人拥有较暗、120px 范围的视锥。
- **幽灵**：方向键自由移动，距猎人最多 120px；Enter 交互。幽灵周围有 100px 的圆形视野，不改变猎人的面向方向。
- 两种视野都受墙体遮挡；敌人和交互对象进入任一可见区域时可见。幽灵可以穿过墙体，门需要幽灵靠近至 64px 内才能交互；其他交互对象仍以猎人 64px 范围为准。
- 幽灵使用 60% 不透明度的青蓝色贴图，始终头朝上。

## 能量与战斗

- obj_team 单例持久化：两个角色共用一个池；初始100，上限100，下限0。
- 实际时间累计1秒恢复1点，满值时不积存恢复时间；跨房间保留能量。
- 每发消耗5点；不足5点不发射。空枪或被墙挡住也耗能。
- 即时射线命中最近的一个敌人就击杀，不穿透敌人或墙；射程700。
- 移动暂不耗能；交互消耗共享能量。

## 框架接口

- obj_player：实体、移动碰撞、射击、交互；自动创建 obj_team 与 obj_aim。
- obj_aim：控制幽灵移动和范围限制，保存猎人的面向方向；ghost_alpha=0.60。
- obj_team：共享池和 GUI 能量条；try_spend(cost)、advance_energy(seconds)。
- par_enemy：未来敌人的父对象；targetable=true，receive_shot(attacker) 默认直接销毁。命中使用敌人的碰撞遮罩；没有贴图时按 hit_radius 设置遮罩。子对象的 Create 需调用 event_inherited()；更换贴图可覆写 Draw，但需保留 coop_visible 判断。
- par_interactable：未来门、开关、拾取物的父对象；enabled、prompt、interact(actor)。幽灵的Enter 选择实体64px内最近的可见对象；交互方法默认只提示，子对象替换实际效果。
- coop_core：沿射线逐像素调用 place_meeting，处理射击、墙体遮挡和共享视野判定。
- obj_wall：实体阻挡移动、瞄准射线和可见性。

保留 rm_01、rm_03 中已有的玩家、墙体和敌人布置；rm_02 由共享管理器自动创建玩家。三个房间均配置一个共享管理器，跨房时自动去重。
以后布置关卡时只需放一个 obj_player，配合继承上述父对象的敌人/交互物。不要同时放两个身体来代表两个玩家，也不必手动放 obj_aim。

## 验证

工程使用本机 GameMaker LTS 2026 runtime 2026.0.0.23 编译检查。
测试只在工作目录的项目副本注入测试对象，不修改正式房间；覆盖恢复、上限、耗能、射线、单次击杀、墙体阻挡、视野与幽灵移动范围。

## 房间与摄像机

仅保留 rm_01 / rm_02 / rm_03。不提供数字键、N/B、PageUp/PageDown 切房快捷键；change_room 接口仅留给后续门或出口使用。
obj_team 跨房间保留共享能量与瞄准方向；没有预放玩家时创建一个安全出生的玩家。
摄像机视野960×540，End Step平滑追踪实体，房间边界钳制，HUD固定在GUI层。
